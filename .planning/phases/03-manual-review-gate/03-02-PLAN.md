Append a new section to the existing lovable-spec.md (after the current progress dashboard section). The addendum must cover all locked decisions from 03-CONTEXT.md:

**Section: Inline Manual Review Form (Phase 3)**

1. **Polling behavior change:**
   - When `data.status === "review_needed"`, keep `refetchInterval` active (2500ms). Do NOT stop polling -- the countdown timer needs live data and the job may auto-continue after timeout.
   - When `data.review_item` is non-null, render the ReviewCard component below the progress section.

2. **ReviewCard component** (rendered when `data.status === "review_needed" && data.review_item`):
   - Service description: read-only text field, pre-filled from `review_item.descricao`
   - Municipality: read-only text field, pre-filled from `review_item.municipio`
   - AI suggestion hint: read-only text showing `review_item.suggested_item_lc` (e.g., "Sugestao IA: 1401")
   - Item LC input: text input, 4-digit mask, required, auto-focused on mount. Validation: exactly 4 digits
   - DDD input: text input, 2-digit mask. ONLY rendered when `review_item.from_n8n === false`. Required when visible. Validation: exactly 2 digits
   - "Pesquisar Item LC" button: `window.open(\`https://www.google.com/search?q=${encodeURIComponent(review_item.item_lc_original + " - codigo item lc " + review_item.municipio + " equivalente goiania")}\`, "_blank")`
   - LC 116 link: anchor to `https://www.planalto.gov.br/ccivil_03/leis/lcp/lcp116.htm` (opens new tab)
   - Confirm button (primary, orange): POST `/jobs/${jobId}/review` with `{ item_lc, ddd (if visible), action: "confirm" }`. Include Supabase JWT in Authorization header.
   - Skip button (secondary, gray): POST `/jobs/${jobId}/review` with `{ action: "skip" }`. Include Supabase JWT.
   - Countdown timer: compute `Math.max(0, Math.floor((new Date(review_item.timeout_at).getTime() - Date.now()) / 1000))`. Update every 1 second via `setInterval`. Display as "Tempo restante: Xm Ys". When reaches 0, show "Tempo esgotado - aceite automatico".

3. **Progress bar behavior during review:**
   - Keep the progress bar at its current percent value
   - Add a pulsing/breathing animation to indicate paused state (CSS animation, not indeterminate)
   - Show text: "Aguardando revisao manual..." above or beside the bar

4. **Post-submit behavior:**
   - After successful POST to `/jobs/${jobId}/review`, invalidate TanStack Query cache for `['job-status', jobId]` to trigger immediate re-poll
   - Do NOT redirect -- the progress page continues showing job progress
   - If POST returns 409 (timeout race), show a toast: "Revisao expirada - nota aceita automaticamente"

5. **API contract for POST /jobs/{jobId}/review:**
   ```
   POST /jobs/{jobId}/review
   Authorization: Bearer {supabase_jwt}
   Content-Type: application/json

   Request body:
   { "item_lc": "1401", "ddd": "62", "action": "confirm" }
   OR
   { "action": "skip" }

   Response (200):
   { "accepted": true }

   Error responses:
   404 — Job not found
   403 — Not your job
   409 — Job is not waiting for review (already timed out or resumed)
   422 — Validation error (item_lc not 4 digits, ddd not 2 digits)
   ```

6. **Updated status type:**
   - Add "review_needed" to the status union: `"queued" | "running" | "review_needed" | "completed" | "failed"`
   - Update the status badge color map: review_needed = amber/yellow

Ensure the addendum is clearly marked as "Phase 3 Addition" so it's obvious what was added vs the original Phase 2 spec.
